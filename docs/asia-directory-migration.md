# Asia 库中断整理后的手工迁移

适用于现有两级结构 `asia/演员名/番号/` → `asia/番号前缀/番号/`，例如：

```text
asia/黒島玲衣/MIAB-576/ → asia/MIAB/MIAB-576/
asia/黒島玲衣/VDD-204/  → asia/VDD/VDD-204/
```

使用独立脚本 `scripts/reorganize_asia.py`，只依赖 Python 3.9+ 标准库，不需要安装本项目或连接 MDCNG。支持 Linux、Windows。Linux 使用 `renameat2(RENAME_NOREPLACE)` 做同一文件系统内不覆盖的目录移动；系统不支持时停止，不回退到复制后删除。

## 在服务器上运行

将脚本上传到服务器，例如 `/root/reorganize_asia.py`。**先停止 MDCNG 中操作 asia 库的刮削、重新整理和监控任务，同时暂停其他对该库的文件写入**；预览到执行期间也保持停止。脚本不能阻止其他程序同时改目录。

先生成清单，不会移动文件，也不删除目录：

```bash
python3 /root/reorganize_asia.py plan \
  --root /mnt/hls2strm_matched/asia \
  --out /root/asia-move-plan.json
```

终端会列出每条待移动路径、冲突和跳过项，JSON 保留完整清单。清单必须在这台服务器生成并执行，并存放在媒体库之外（日志也写在清单旁边），避免它们改变待迁移目录。清单记录文件系统身份和大小、修改时间，不是可跨机器复用的配置。已有清单不会被覆盖；重新预览时换一个文件名。

确认待移动路径符合预期后执行：

```bash
python3 /root/reorganize_asia.py apply --plan /root/asia-move-plan.json
```

执行将整部影片目录搬走，STRM、NFO、封面、字幕及 `extrafanart` 一起移动，文件名和内容保持原样。成功后只用 `rmdir` 清理本次移动产生的空演员父目录，不递归删除，不清理其他目录。目录名中的 `-破解`、`-流出` 等后缀原样保留。

若 SSH 断开、Ctrl+C 或执行失败，排除报错原因后，**再次执行同一条 apply 命令**。已搬完的目录按文件系统身份核对后跳过；尚未搬完的继续执行。每次移动前后追加到 `/root/asia-move-plan.json.journal.jsonl`。日志或清单含路径但不读取、记录 STRM 中的播放 URL。

## 处理边界

- 已经位于 `asia/前缀/番号/` 的影片保持原位。
- 只处理两级结构，影片目录名称需要符合普通 `前缀-数字` 番号格式，并且目录直属文件中至少有一个 `.strm`。不会从影片标题猜番号。
- FC2、HEYZO、日期型番号、其他非标准目录单独列为跳过。它们涉及原方案的年份/厂商布局，不在这次普通番号迁移范围内；顶层 `2021`、`Tokyo Hot (東京熱)` 等不能整批改成前缀目录。
- 同一番号出现在多个演员目录、目标已存在（包括空目录）、目录含软链接、Windows 目录联接或其他重解析点、特殊文件时，保留原状并报告。不覆盖、不合并、不删除重复影片。
- 清单中的冲突和跳过项不阻止其他无冲突目录迁移；退出码 `2` 表示仍有未处理项，`0` 表示清单项全部处理，`1` 表示错误停止，`130` 表示手动中断。
- 预览后源目录发生变化、目标新出现或路径越界，会在执行前停止；执行期间再次发现源目录变化也会停止。检测依据是文件系统元数据，不是逐文件内容校验。
- 脚本只操作指定根目录，不修复先前误搬到 `/mnt/hls2strm_matched/` 下的中文字幕，也不修改 MDCNG 数据库中的 `target_path`、`target_dir` 或任务状态。

## 移动后

再用新的清单文件做一次 `plan`，确认普通番号待移动数量为 `0`，查看剩余冲突和跳过项。然后在 hls2strm 对 asia 对应的输出库执行“同步位置”，让 Emby/Jellyfin 扫描该库。

MDCNG 旧刮削记录仍指向旧路径，手工搬目录不会自动同步它的数据库；不要直接对这些旧记录再次点击“重新整理”。恢复 asia 库任务前，确认它们的整理目录仍为 `/mnt/hls2strm_matched/asia`，并使用新的命名规则。若要继续操作 MDCNG 的历史记录，需要另外按实际数据库/API 核对和修复路径，不可用本脚本的执行结果假装数据库也已更新。
