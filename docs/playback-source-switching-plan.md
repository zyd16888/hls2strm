## 当前实现与验证记录

- `playback_selection.py` 负责有限媒体预检、30 秒成功缓存、5 分钟候选冷却和预算内回退；主动排除不会记成源故障。
- `use-playback-source.ts` 负责准备信息、手动/自动换源、候选排除、恢复预算和进度状态。自动换源最多 3 次、30 秒恢复预算；稳定播放 30 秒后重置预算。
- 实际源在视频进度开始推进后显示。整体试播默认自动，指定源默认不自动扩展；用户可以主动切回全源。
- 直连覆盖沿用旧 `proxy` 配置，增加 `direct_mode=auto/allow/proxy`。DooPlayer 仍采用保守自动策略，显示 IP 限制待验证，不伪造跨 IP 实测结论。
- 外部连续模式实现为按需 VOD 分片，每片 6 秒，固定 H.264/AAC、30fps、双声道，片间声明 discontinuity。当前统一转码，暂不做跨源重封装优化。默认关闭；默认 2 个进程、4 个会话、128 MB 完成分片缓存、45 秒单片总预算；临时分片另有每片 16 MB 限额。并发改变后需重启。
- 本地真实 FFmpeg 验证：先请求尾片再请求首片成功；确认视频 H.264、音频 AAC 48kHz 双声道，分片时间戳处于对应位置。模拟主 MP4 上游失效后，后续分片换到 HLS 备用源，实际解码画面来自备用源。
- 浏览器验证：真实源展示，手动换源恢复进度、1.5 倍速与 0.4 音量，模拟播放错误自动切源，暂停 10 秒不触发换源，指定源范围不被扩大；桌面和 390px 页面无脚本错误。
- 本地验证不代表真实外部客户端或生产 CPU 容量已通过。当前未部署，也未修改生产配置；仍需在实际环境启用前验收。

## 已确认的现状

- 网页整体试播只传作品地址，界面不知道最终选中的站点和线路。后端 `Resolved` 已有实际源、线路、播放站和媒体地址，可以从播放会话提供，不能拿数据库各站的 `source.line` 当作正在播放的源。
- `Resolver` 已有单候选尝试预算和总预算；当前主要覆盖取址。HLS 清单、媒体下载失败发生在选源完成之后，未形成完整的起播候选回退。
- `HealthTracker` 默认将慢、不稳、不通的播放站降序，不删除源，也不替换活动会话。当前按播放站聚合，不能据此断言某位 302 客户端到 CDN 的速度。
- 中转会话固定源、线路与地址快照，防止并发播放器串线。跨源切换需要建立新的播放会话，不能直接修改所有活动会话引用的源。
- 网页最高画质与跨源排序是两层逻辑：前者选择同一播放清单中的档位；后者继续遵守字幕偏好、连通性、画质上限和站点顺序。

## 第一阶段：共享起播策略与网页换源

### 实际源展示

播放准备结果提供：播放会话标识、作品、源 ID、站点名称、线路 ID/名称、播放站、媒体类型、实际传输方式、已知画质及其来源。

播放器显示例如：`当前源：JAVMost · DOO / DooPlayer · MP4 · 中转`，画质根据播放器实际解码高度更新；准备时显示“正在选源”，不能提前把候选标为播放成功。切换期间显示原源、候选源和原因，新源实际推进播放后才更新为“当前源”。

外部播放的信息可放在服务端播放会话详情中。纯 302 显示“已返回直链”，不能宣称外部客户端已经成功播放。

### 起播时规避慢源

1. 复用现有源/线路排序。明确不可用及近期失败的候选靠后；可正常播放的候选中优先高画质，并遵守字幕和画质上限设置。
2. 在现有总预算内，将检查延伸到实际 CDN：HLS 检查目标画质清单和有限的首片数据，MP4 使用有限 Range 数据。取址成功不直接等于起播成功。
3. 串行按需尝试候选，不默认同时下载所有源。缓存最近检测结果，避免每次播放重新测速全部站点。
4. 超时或媒体校验失败后尝试下一候选。单次小样本速度只作参考，结合首字节、历史结果和目标码率；不把高画质流的正常带宽需求误判为源坏了。
5. 慢源进入临时冷却/降序，不删除源记录；冷却后允许恢复。若没有更好的源，仍可明确提示后使用慢源。

共享起播逻辑供网页、STRM `/play` 和网关 `/api/resolve` 使用。对 302，服务端检测仅证明服务器到 CDN 的可达性，无法代替客户端实际速度。

### 网页播放中换源

- 整体试播提供“自动换源”和“换一个源”。指定站点/线路试播默认保持指定范围，避免测试 A 实际悄悄播放 B；允许用户主动回到全源自动选择。
- 以播放进度和缓冲状况判断卡顿，不按单个低速分片立即切换。建议初始阈值：期望播放、缓冲不足且连续 8 秒无进度；暂停、拖动恢复期、播放结束及浏览器挂起不计作慢源。阈值后续按实测调整。
- 网络错误先按原线路恢复策略重试一次；持续卡顿、重试失败或用户主动换源时，记住真实 `currentTime`、暂停状态、音量、倍速和画质选择。
- 后端排除本轮已经失败的源/线路，选下一候选并建立新会话。排除粒度为源和线路，不因一个影片失败而永久封禁整个站点。
- 前端销毁旧加载器、加载新会话，元数据就绪后按时间续播。优先保留原画质或更高档，缺少原档时明确显示实际档位。
- 建议一次自动恢复最多尝试 3 个不同候选，并受总恢复预算限制；失败后停止循环，显示失败原因并允许手动选择/重试。
- 只在同一作品和允许的字幕/版本范围内切换。明显时长不一致的源不自动续接；时长接近也不保证片头和剪辑完全一致，界面需说明按时间续播可能有位置偏差。不能承诺跨站无缝切换。
- 页面关闭或新一轮播放开始时取消旧准备、加载与恢复请求，旧结果不得覆盖新会话。

## 第二阶段：外部播放器的连续自动换源

| 输出方式 | 起播避开慢源 | 播放中服务端自动换源 |
| --- | --- | --- |
| 302 直连 CDN | 可以做服务端预检和排序 | 通用情况下无法控制；后续媒体请求不经过本服务 |
| 现有 MP4/HLS 原样中转 | 可以 | 能检测异常；不能安全地把任意另一站媒体直接接上 |
| 新增稳定 HLS 输出模式 | 可以 | 可由服务端在统一时间轴上切换上游，需要单独实现媒体处理管线 |

建议新增可选的“连续播放”模式，保留现有 302 和轻量中转。STRM/网关返回固定 HLS 会话地址，外部播放器始终读取这一份输出。

实现要求：

1. 使用受管理的 FFmpeg 管线取流、定位和切换，输出稳定的分片序列和时间轴；处理初始化段、时间戳、音视频同步及必要的 discontinuity。
2. 可兼容的源尝试重封装；编码、分辨率或音频参数无法稳定衔接时需要统一转码。单纯把 MP4 字节范围改映射到另一个文件不可行。
3. 上游异常时停止旧输入，在新源相应时间点重新建立输入，输出序号不回退；定位精度受关键帧、源站 Range/seek 支持和内容版本影响。
4. 对输出缓冲、临时空间、并发转码和会话寿命设上限；客户端离开、长期无分片请求、任务失败时释放进程和文件。
5. 正常播放与任意拖动都要验证。拖动至尚未输出的位置需要明确的 VOD seek/重建策略，不能把直播式滚动清单当作已具备完整点播能力。
6. 客户端兼容性分别验证 Emby、Infuse 等实际使用链路。仅本地 ffmpeg 能拉取不算外部播放器验收通过。

这部分会增加服务端带宽、磁盘缓存和可能的 CPU/GPU 成本，建议第一阶段完成后再按服务器资源与实际客户端确定实施范围。若暂不引入媒体处理管线，外部播放器只能提供更好的起播选源与重新打开时避开坏源，不能称为播放中自动换源。

## JAVMost / DooPlayer IP 绑定复核

`HOST_TRAITS['dooplayer'].ip_bound=True` 是适配器硬编码，界面和外网解析筛选均使用它；它不是运行时自动检测结果。现有单元测试只验证取址，不验证跨公网 IP 播放。

此前已实测本例 `SNOS-372-REDUCING-MOSAIC` 的 JAVMost → DooPlayer → `cdn.mostplayer.com` 取址成功；CDN 返回 206、`video/mp4`，文件头含 MP4 `ftyp`。这能证明同出口取址及读取正常，不能证明绑定或不绑定 IP。

本轮用直连和现有本地 HTTP 代理访问公网 IP 查询接口，两者出口相同，因此没有形成有效的跨 IP 对照；官方播放器脚本混淆，也没有提供可直接确认 IP 限制的公开字段。用户报告的换 IP 成功与现有硬编码结论冲突，现有“绑 IP”标签不应当作已验证事实。

验证方案：出口 A 只取一次直链；出口 A、B 使用完全相同的 URL，在不刷新 token 的前提下分别发有限 Range 请求，核对 206、Content-Range、媒体类型及样本字节。再反向取址验证，并抽查多部影片，区分 IP、Cookie、Referer、地区及 token 过期的影响。

策略建议：

- 对这类未确认限制显示“IP 限制待验证”，区分观测事实和保守策略。
- 增加线路级直连策略覆盖，允许选择“自动 / 允许外部直连 / 强制中转”，保留用户已明确验证的环境差异。
- 跨 IP 验证通过后，将 DooPlayer 的默认 `ip_bound` 改为 false，并同步网关选源测试、页面说明和 README；不同时修改 VidHide、VOE 等其他播放站。
- 即使直链不绑 IP，网页仍可为了 CORS、会话恢复和可观测性使用中转；外部播放器则可以直接 302。

## 验收与实施顺序

第一阶段先完成源展示、共享起播候选回退、网页手动换源，再接入有次数与冷却限制的自动换源。JAVMost 跨 IP 复核可独立进行。

需要覆盖的回归：

- 自动选源时显示实际站点和线路，缓存命中与故障回退均正确；多播放器并发不串源。
- 取址成功但 CDN 失败、首片超时、慢源恢复、候选耗尽、指定线路约束。
- HLS 与 MP4 双向换源后按时间续播，音量、倍速、暂停状态不丢失。
- 暂停、拖动、结束、关闭弹窗、切换作品不会误触发自动换源或留下下载。
- 字幕不回退、作品版本隔离、画质偏好、会话过期/服务重启恢复。
- 外部 302 仅记录已返回直链，不伪造客户端卡顿或成功数据。

第二阶段另验稳定 HLS 的时间轴、字幕音轨、任意拖动、进程回收、并发资源上限，以及真实 Emby/Infuse 客户端表现。
